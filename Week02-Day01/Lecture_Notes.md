# Week 02 Day 01 - Database Fundamentals

> 원본 강의자료: `week02day01.pdf` (29쪽)

## 학습 목표

- 데이터베이스, DBMS, 테이블과 엔터티의 관계를 설명한다.
- 스키마, 기본키와 외래키로 데이터 구조를 설계한다.
- DDL과 DML을 이용해 테이블을 만들고 데이터를 처리한다.
- 인덱스의 역할과 적용 기준을 이해한다.

## 기본 용어

| 용어 | 의미 |
| --- | --- |
| Database | 관련 데이터를 구조적으로 모아 관리하는 저장 공간 |
| DBMS | 데이터 정의, 저장, 조회, 보안과 복구를 담당하는 소프트웨어 |
| Entity | 서비스가 관리하려는 대상 |
| Table | 엔터티 데이터를 행과 열로 저장하는 구조 |
| Row | 하나의 레코드 또는 인스턴스 |
| Column | 레코드가 가지는 속성 |
| Schema | 테이블, 컬럼, 타입, 관계와 제약 조건을 정의한 설계 |

데이터베이스는 통합성, 저장성, 운영성, 공유성을 갖는다. 여러 사용자가 같은 데이터를 사용하더라도 DBMS가 무결성과 동시성을 관리한다.

## 키와 관계

- Primary Key: 각 행을 유일하게 식별한다.
- Foreign Key: 다른 테이블의 기본키를 참조해 관계를 만든다.
- NOT NULL: 반드시 값이 있어야 하는 컬럼을 표시한다.
- UNIQUE: 중복을 허용하지 않는 업무 식별자를 보호한다.

쇼핑몰 예제에서는 회원, 상품, 주문을 각각 분리하고 주문 테이블이 회원과 상품의 키를 참조한다. 데이터 중복을 줄이고 가격, 회원 정보, 주문 상태를 일관되게 관리하기 위한 구조다.

## 스키마의 세 관점

1. 외부 스키마: 사용자나 화면별로 필요한 데이터 관점
2. 개념 스키마: 전체 데이터 구조와 관계를 표현한 논리 설계
3. 내부 스키마: 파일, 인덱스와 저장 방식 같은 물리 설계

## SQL 분류

| 분류 | 대표 명령 | 목적 |
| --- | --- | --- |
| DDL | `CREATE`, `ALTER`, `DROP` | 데이터 구조 정의 |
| DML | `INSERT`, `UPDATE`, `DELETE` | 데이터 변경 |
| Query | `SELECT` | 데이터 조회 |
| DCL | `GRANT`, `REVOKE` | 권한 관리 |
| TCL | `COMMIT`, `ROLLBACK` | 트랜잭션 확정과 취소 |

## 예제 흐름

1. 회원과 상품 테이블을 생성한다.
2. 기본키와 데이터 타입을 지정한다.
3. 주문 테이블에 회원과 상품 외래키를 설정한다.
4. 샘플 데이터를 입력하고 `SELECT`로 검증한다.
5. 주문 데이터를 변경한 뒤 예상 결과와 비교한다.
6. 자주 검색하는 컬럼에 인덱스를 만들고 조회 조건을 점검한다.

인덱스는 조회 속도를 높이지만 저장 공간을 사용하고 입력과 수정 비용을 늘린다. 조회 빈도와 선택도가 높은 조건부터 적용하고 실행 계획으로 효과를 확인해야 한다.
