# Week 01 Day 05 - AI Algorithm Project Lab

> 원본 강의자료: `week01day05.pdf` (20쪽)

## 학습 목표

- 실무 문제를 데이터와 판단 기준으로 구조화한다.
- 데이터 수집 범위, 입력과 출력, 알고리즘을 연결한다.
- 문서 관리 또는 판매 데이터 분석 미니프로젝트를 설계한다.
- 작은 결과를 검증하고 발표 가능한 산출물로 발전시킨다.

## 문제 해결 흐름

```text
문제 정의 -> 데이터 수집 -> 입력/출력 설계 -> 알고리즘 선택 -> 작은 예제 구현 -> 검증 및 발표
```

코드를 먼저 작성하기보다 다음 질문을 먼저 정리한다.

- 누가 어떤 불편을 겪고 있는가?
- 어떤 데이터를 어떤 권한으로 수집할 수 있는가?
- 데이터의 필드, 단위, 수집 주기와 민감 정보 여부는 무엇인가?
- 분류, 탐색, 정렬, 집계, 추천 중 핵심 알고리즘은 무엇인가?
- 정답 예시와 예외 사례를 어떻게 검증할 것인가?

## 프로젝트 A - 기업 문서 정리 및 관리

폴더와 채널에 흩어진 문서를 빠르게 찾고 중복 문서와 오래된 문서를 줄이는 도구를 설계한다.

### 데이터

- 경로, 제목, 부서, 확장자, 작성일과 버전
- 문서 본문의 첫 부분 또는 요약
- 태그, 접근 권한, 민감 정보 여부

### 알고리즘 후보

- 키워드 매칭과 태그 분류
- 유사도 비교를 이용한 중복 탐지
- 그래프 탐색을 이용한 관련 문서 묶음

### MVP

- 문서 목록 업로드
- 자동 태그 추천
- 검색어 기준 추천 문서 5개
- 중복 의심 문서와 추천 이유 표시

평가는 정답 문서가 상위 결과에 포함되는지, 사용자가 잘못된 태그를 고칠 수 있는지, 민감 문서가 노출되지 않는지를 기준으로 한다.

## 프로젝트 B - 온라인 판매 제품 분석

판매 지표와 후기 데이터를 연결해 판매 전략과 상품 개선 아이디어를 만든다.

### 데이터

- 상품명, 카테고리, 가격, 판매량과 재고
- 평점, 후기 문장, 작성일
- 반품과 문의 유형, 프로모션 기간
- 검색 순위, 배송 유형과 반복 키워드

### 알고리즘 후보

- 판매량과 매출 정렬
- 카테고리별 집계
- 후기 키워드 빈도 분석
- 간단한 긍정과 부정 점수

### MVP

- CSV 판매 데이터 업로드
- 상품별 판매와 평점 요약
- 후기 키워드 Top 5
- 개선 우선순위와 상품 개발 제안

플랫폼 약관과 공개 범위를 확인하고, 개인정보는 저장하지 않으며, 수집 시점과 조건을 기록해야 한다.

## PBL 진행 방식

1. 사용자와 문제를 한 문장으로 좁힌다.
2. 공개 데이터와 내부 데이터를 구분하고 샘플 20~50건을 준비한다.
3. 외부전문가, 내부전문가, 실행팀의 역할을 정한다.
4. 핵심 알고리즘과 입출력 예시를 먼저 구현한다.
5. 정상 사례와 실패 사례를 기록하고 중간 피드백을 반영한다.
6. 문제 정의, 데이터 수집표, 알고리즘 선택 근거, 결과와 한계점을 발표한다.

## 최종 발표 구성

- 문제와 사용자 상황
- 데이터와 사용 원칙
- 적용 알고리즘과 선택 이유
- 분석 결과와 제품 개발 제안
- 한계점과 다음 단계
- 팀원별 역할과 회고
