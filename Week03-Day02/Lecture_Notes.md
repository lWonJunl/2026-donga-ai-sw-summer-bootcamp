# Week 03 Day 02 - Frontend and Backend Fundamentals

> 원본 강의자료: `week03day02.pdf` (29쪽)

## 학습 목표

- 프론트엔드와 백엔드의 역할을 구분한다.
- 사용자의 요청이 서버 처리와 응답으로 이어지는 흐름을 설명한다.
- 화면 기능을 프론트엔드 책임과 백엔드 책임으로 나눈다.
- UI/UX, 보안과 안정성이 서비스 품질에 미치는 영향을 이해한다.

## 웹 서비스의 큰 흐름

```text
사용자 입력 또는 클릭
  -> 프론트엔드가 요청 생성
  -> API를 통해 백엔드로 전달
  -> 백엔드가 규칙 확인 및 데이터 처리
  -> 응답 반환
  -> 프론트엔드가 결과를 화면에 표시
```

식당에 비유하면 사용자가 보는 홀은 프론트엔드, 주문을 확인하고 실제 처리를 수행하는 주방은 백엔드에 가깝다. 두 영역을 나누면 역할과 책임이 명확해지고 협업, 유지보수와 보안 관리가 쉬워진다.

## 프론트엔드

프론트엔드는 사용자가 직접 보고 조작하는 영역이다.

### 주요 책임

- 화면 구조와 콘텐츠 표시
- 사용자 입력과 클릭 처리
- API 요청 생성과 응답 표시
- 로딩, 오류와 빈 상태 안내
- 다양한 화면 크기와 접근성 대응

### 핵심 기술

| 기술 | 역할 |
| --- | --- |
| HTML | 콘텐츠와 화면 구조 |
| CSS | 색상, 배치, 크기와 반응형 디자인 |
| JavaScript | 사용자 동작과 동적 화면 처리 |

복잡한 화면은 React, Vue, Angular 같은 도구로 컴포넌트 단위로 나눌 수 있다. UI는 화면 요소와 배치를 뜻하고, UX는 사용자가 서비스를 이용하며 겪는 전체 경험을 뜻한다.

프론트엔드에서는 느린 화면, 모호한 버튼, 입력 검증 부족, 오류 안내 누락과 접근성 문제를 주의해야 한다.

## 백엔드

백엔드는 사용자에게 직접 보이지 않지만 서비스의 실제 판단과 데이터 처리를 담당한다.

### 주요 책임

- API 요청 수신과 응답 생성
- 비즈니스 규칙 검증
- 데이터베이스 조회와 변경
- 로그인, 권한과 세션 관리
- 외부 서비스 연동
- 로그, 오류와 운영 상태 관리

### 주요 구성 요소

- Application Server
- Database
- API
- Authentication and Authorization
- Logging and Monitoring

Python/Django, Java, Node.js와 같은 서버 기술과 MySQL/PostgreSQL 같은 데이터베이스를 조합할 수 있다. 기술 이름보다 요청 처리와 데이터 관리 책임을 먼저 이해해야 한다.

## 서비스 예시

### 로그인

1. 프론트엔드가 아이디와 비밀번호를 입력받는다.
2. 백엔드가 계정과 비밀번호를 검증한다.
3. 성공하면 세션 또는 토큰을 발급한다.
4. 프론트엔드가 로그인 결과를 표시한다.

비밀번호 검증과 권한 판단은 화면이 아니라 서버에서 수행해야 한다.

### 주문 처리

버튼 한 번의 뒤에서는 상품과 수량 확인, 가격 계산, 재고 검증, 주문 저장, 결제와 배송 처리 등이 이어진다. 프론트엔드는 주문 내용을 표시하고 요청을 전달하며, 백엔드는 데이터의 정확성과 처리 순서를 보장한다.

## 역할 분리 실습

기능을 설계할 때 다음 질문으로 책임을 나눈다.

- 사용자가 직접 보고 조작하는가?
- 서버에서 다시 검증해야 하는 규칙인가?
- DB에 저장하거나 조회해야 하는가?
- 다른 사용자에게 노출되면 안 되는 정보인가?
- 실패했을 때 화면과 서버가 각각 어떤 안내와 기록을 남겨야 하는가?

## 핵심 정리

- 프론트엔드는 사용자 경험과 화면 상호작용을 담당한다.
- 백엔드는 데이터, 비즈니스 규칙, 인증과 보안을 담당한다.
- 두 영역은 API의 요청과 응답을 통해 협력한다.
- 클라이언트 입력은 신뢰하지 않고 서버에서 반드시 다시 검증한다.
- 역할 분리는 협업뿐 아니라 서비스 안정성과 확장성을 높인다.
