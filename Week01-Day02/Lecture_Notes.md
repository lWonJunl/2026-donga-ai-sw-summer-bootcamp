## 그리디 알고리즘

그리디 알고리즘은 현재 상태에서 가장 유리해 보이는 선택을 반복하는 문제 해결 전략이다. 구현 전에 다음 세 요소를 명확히 정해야 한다.

1. 상태: 현재까지 선택한 결과와 남은 문제
2. 선택 기준: 매 단계에서 가장 먼저 고를 후보
3. 종료 조건: 선택을 멈추고 결과를 반환할 시점

그리디 전략이 최적해를 보장하려면 지역 최적 선택을 이어도 전체 최적해에 도달하는 문제 구조가 필요하다. 조건이 맞지 않으면 DP, 완전 탐색 또는 다른 최적화 방법을 검토해야 한다.

## 예제 1 - 동전 거스름돈

일반적인 화폐 단위에서는 큰 동전부터 가능한 만큼 사용하는 방식으로 동전 개수를 줄일 수 있다.

```text
사용 개수 = 남은 금액 // 동전 단위
남은 금액 = 남은 금액 % 동전 단위
```

풀이 순서는 다음과 같다.

1. 동전 단위를 내림차순으로 정렬한다.
2. 현재 단위로 만들 수 있는 최대 개수를 선택한다.
3. 몫을 결과에 더하고 나머지를 다음 상태로 넘긴다.
4. 남은 금액이 0이 될 때까지 반복한다.

단, 동전 체계가 임의로 주어지면 큰 동전부터 고르는 방식이 최소 개수를 보장하지 않을 수 있다. 반드시 작은 반례를 만들어 전략의 타당성을 확인해야 한다.

## 예제 2 - 회의실 배정

가장 많은 회의를 배정하려면 종료 시간이 빠른 회의부터 선택한다.

1. 회의를 종료 시간 기준으로 정렬한다.
2. 종료 시간이 같으면 시작 시간으로 순서를 보완한다.
3. 선택한 회의의 종료 시각 이후에 시작하는 회의만 추가한다.
4. 마지막 종료 시각을 상태로 갱신한다.

종료 시간이 빠른 회의를 선택하면 이후 회의를 배정할 수 있는 남은 시간이 최대가 된다.

## 적용 판단

| 상황 | 그리디 적용 관점 |
| --- | --- |
| 데이터가 매우 많음 | 전체 경우를 비교하기 어려울 때 빠른 판단에 유리하다. |
| 실시간 응답 필요 | 즉시 자원이나 작업을 배정해야 할 때 사용할 수 있다. |
| 최적 구조가 증명됨 | 회의실 배정처럼 최적해를 보장할 수 있다. |
| 근사 결과로 충분함 | 완벽한 최적해보다 빠르고 충분히 좋은 답이 중요할 수 있다. |

서버 작업 배정에서는 현재 가장 여유 있는 서버를 선택하는 방식이 그리디 예시가 될 수 있다. 다만 장기 부하와 작업 특성까지 고려해야 실제 시스템에서 안정적이다.
